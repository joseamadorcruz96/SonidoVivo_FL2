# Planilla de Especificación de Requerimientos de Software (ERS) - Simplificada
## Proyecto: Tienda Online "Sonido Vivo" (Forma B - DSY1104 Full Stack II)
### Avance Consolidado del Proyecto - Evaluaciones Parciales 1, 2 y 3 (Frontend React, Backend Microservicios Spring Boot y Despliegue Cloud)

El presente documento consolida la matriz unificada de **51 Requerimientos Funcionales (RF)** y **17 Requerimientos No Funcionales (RNF)** para el proyecto de tienda online **"Sonido Vivo"**, correspondiente a la asignatura **Desarrollo Full Stack II (DSY1104)**, cumpliendo con el estándar del **Anexo 2 - Planilla de Requerimientos**.

Esta especificación cubre la evolución integral del proyecto:
1. **Evaluación Parcial 1 (Semana 4)**: Frontend básico, catálogo con filtrado, carrito de compras inicial y validaciones de formularios con JavaScript elemental.
2. **Evaluación Parcial 2 (Semana 8 - Fases 1 y 2)**: Migración a Single Page Application (SPA) con **React 19 / Vite**, incorporación de vistas de tienda (`feature/tienda-vistas`: Categorías, Ofertas, Checkout y Confirmaciones de Pago), sistema administrativo modular (`feature/admin-vistas`: Dashboard con Recharts, Órdenes y Boletas, Mantenedor de Categorías, Reportes, Perfil, Usuarios e Historial de Compras, y Stock Crítico), y suite de testing unitario automatizado con Vitest y reporte de cobertura V8.
3. **Evaluación Parcial 3 (Integración Full Stack y Nube)**: Construcción de arquitectura backend de microservicios con **Spring Boot 4.1.2** (`api-gateway`, `ms-usuarios-auth`, `ms-catalogo-inventario`, `ms-ventas-boletas` con OpenFeign), seguridad **Spring Security + JWT + BCrypt** y roles (`ADMIN`, `VENDEDOR`, `CLIENTE`), persistencia **Database-per-Service en Supabase PostgreSQL** con migraciones **Flyway**, documentación **OpenAPI / Swagger**, eliminación total de mocks en React (`axios` + interceptores + RBAC) y despliegue productivo en **AWS EC2** detrás de **Nginx**.

### Definiciones de Columnas y Criterios (Según Anexo 2)

| Columna | Definición |
| :--- | :--- |
| **[R-N°]** | Identificador único y correlativo del requerimiento (ej. RF-01, RNF-01). |
| **[Nombre del Requerimiento]** | Nombre descriptivo de alto nivel asignado al requerimiento. |
| **Tipo Requerimiento** | Categoría principal: **Funcional** o **No Funcional**. |
| **Clasificación** | Clasificación formal: *Funcional de usuario*, *Funcional de sistema*, *No funcional de producto*, *No funcional de la Organización*, *No funcional Externos*. |
| **Actores Relacionados** | Actor principal que interactúa o se beneficia del requisito (Cliente, Vendedor, Dueño / Administrador, Sistema). |
| **[Descripción corta del requerimiento]** | Resumen conciso del alcance y comportamiento esperado de la función o restricción técnica. |
| **Criterios de Aceptación** | Condiciones observables, verificables y de prueba para declarar el requerimiento como completado satisfactoriamente. |
| **Estado** | Estado del requerimiento dentro del ciclo de desarrollo (Solicitado, Aprobado, En Desarrollo, Completado). |

### Etapa 4: Formularios de Usuario y Vistas Institucionales (EP1)
